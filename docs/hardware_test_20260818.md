**모터를 한 번도 돌리지 않은 read-only 점검**이다. 목적은 두 가지였다 — MD400 2 대와 Pico 가
정상 연결돼 있는지, 그리고 **Pico 의 전압·전류가 제대로 읽히는지**.

설명되지 않는다.**

> 회로 변경 사실과 DMM 27.14 V 는 운영자 구두 보고다. **바뀐 저항값은 아직 모른다** —

## 4. 분압비 역산

`raw = 4095 · (V_bus/D) / V_rail` 이므로 **`V_rail · D = V_bus · 4095 / raw`** 다.
좌변은 DMM 과 raw 로 직접 측정되지만, **D 와 V_rail 은 곱으로만 나타나 분리되지 않는다.**

측정: DMM **27.14 V** ↔ GP26 raw **3021.76** (σ 0.89, n=1531, 30 s)

### 레일을 몰라도 확정되는 것

| 항목 | 값 | 현재 펌웨어 대비 |
|---|---:|---:|
| `v_per_lsb` (실효) | **8.9815 mV/LSB** | 9.1312 → **−1.64%** |
| `V_rail · D` | **36.7793** | — |
| `DIV_RATIO` 유지 시 | `scale_v` = **0.98361** | |
| `scale_v`=1 유지 시 | `DIV_RATIO` = **11.1453** | 호스트 규약 (VREF 3.3 V 가정) |

### 물리 분압비는 레일의 함수

| 가정 V_rail | D = 1+R1/R2 | R1/R2 | 근거 |
|---:|---:|---:|---|
| **3.3134** | **11.100** | **10.100** | 전류센서 영점 역산 (조치 #18) ← 최선 추정 |
| 3.3000 | 11.145 | 10.145 | Pico 3V3 공칭 |
| 3.2761 | 11.227 | 10.227 | 8/14 교정 시점 레일 |

**▶ D ≈ 11.10 ± 0.07 (±0.6%)** — 불확실도는 거의 전부 레일에서 온다 (§5 에서 보듯 지금
레일 추정치는 ±0.5% 로만 믿을 수 있다). DMM 정밀도와 시각 어긋남은 합쳐서 ±0.1% 뿐이다.

> **옛 `DIV_RATIO` 11.3310 은 물리 분압비가 아니다.** 8/13 에 레일을 3.3 V 로 가정해 적합한
> 값이라 그날의 실제 레일이 통째로 흡수돼 있다. 같은 기준으로 환산하면 8/15 물리값은 11.397 이고
> 오늘은 11.100 — **분압비 변화분은 −2.6%** 다. raw→V 가 −1.64% 인 것은 레일 +0.99% 가 일부
> 상쇄했기 때문이다.

### 저항값을 알아내면 레일이 풀린다

`V_rail = 36.7793 / D` 로 역으로 푼 뒤 전류센서 영점 역산(3.3134 V)과 대조하면 **전류 채널의
신뢰성까지 함께 판정된다.**

| D | → V_rail | 영점역산과 차 | 판정 |
|---:|---:|---:|---|
| 11.0 | 3.3436 | +0.91% | 경계 |
| 11.0656 | 3.3238 | +0.31% | 일치 |
| 11.1 | 3.3135 | +0.00% | 일치 |
| 11.2 | 3.2839 | −0.89% | 불일치 |
| 11.3310 | 3.2459 | −2.04% | 불일치 |

- 차이 ±0.5% 안 → 두 계측계 일치. §5 의 영점 이동은 **전류 자체의 변화**로 봐야 한다.
- 레일은 타당(3.2~3.4 V)한데 차이가 크다 → **전류센서 쪽이 틀렸다.**
- 레일이 3.2~3.4 V 밖 → 분압 말고 다른 것도 바뀌었다.

**⚠ 1 점 적합이다.** 게인 오차와 오프셋 오차를 구분하지 못한다 — `pico/main.py:57` 이 8/13
적합에 대해 경고한 것과 정확히 같은 한계다. 오프셋이 섞여 있으면 다른 전압에서 다시 틀어진다.
2 점(예 24 V / 28.8 V) 대조 전까지 확정이 아니다.

## 5. 전류 채널 — 분압과 무관한 별도 변화

전압 쪽은 회로 변경으로 설명된다. **전류 쪽은 설명되지 않는다.**

### 채널간 영점차가 부호를 바꿨다

| 세션 | gp28 | gp27 | 차 (gp28−gp27) | 전류 환산 |
|---|---:|---:|---:|---:|
| 8/11 | 2068.04 | 2052.92 | +15.12 LSB | +182 mA |
| 8/12 | 2070.10 | 2053.44 | +16.66 | +200 mA |
| 8/13 | 2066.98 | 2052.62 | +14.36 | +173 mA |
| 8/14 | 2067.20 | 2057.86 | +9.34 | +112 mA |
| 8/15 | 2066.55 | 2052.30 | +14.25 | +171 mA |
| **8/18** | **2037.75** | **2040.59** | **−2.84** | **−34 mA** |

**레일은 두 채널을 같은 비율로 움직이므로 이 차를 만들 수 없다** (1% 레일 변화가 15 LSB 차에
주는 영향은 0.15 LSB 뿐이다). 약 17 LSB ≈ 200 mA 의 차동 성분이 새로 생겼다.

### 레일 역추정이 자기모순이다

채널 하나씩만으로 8/15 대비 레일 비를 구하면:

```
gp28 만으로 :  2066.55 / 2037.75 = 1.01413  →  레일 +1.41 %
gp27 만으로 :  2052.30 / 2040.59 = 1.00574  →  레일 +0.57 %
                                     차 0.84 %p  ← 순수 레일이면 0 이어야 한다
```

`calibrate_zero()` 는 두 채널을 평균하므로 이 모순을 **숨긴 채** 3.3134 V 를 낸다. 그래서 §4 에서
레일 불확실도를 ±0.5% 로 잡았다.

### 분해 — 레일 +0.99% + 채널당 −102 mA

두 채널의 전류가 같은 양 `x` 만큼 변하고 레일 비가 ρ 라 두면 (부호가 반대라 `x` 가 반대로 들어간다):

```
2066.55·(ρ−1) + x = −28.80        (gp28)
2052.30·(ρ−1) − x = −11.71        (gp27)
   ⟹  ρ−1 = −0.98 %  (레일 +0.99 % = 3.3134 V)
        x  = −8.48 LSB = −102 mA   (채널당)
```

**가설**: 컨트롤러 대기전류(DMM 실측 0.077 A ≈ 6.4 LSB)가 더 이상 센서를 통과하지 않는다면
예상되는 값이 −6.4 LSB 다. 실측 −8.48 LSB 와 **방향이 같고 크기도 비슷하다.** 회로를 손대면서
센서 IP 배선이나 급전 경로가 바뀌었을 가능성이 있다.

**확정은 아니다.** 이 분해는 "두 채널의 전류 변화가 같다"는 가정과 8/15 의 레일 추정치에
기대고 있다. §4 의 저항값이 들어오면 레일이 독립적으로 풀리므로 그때 판정된다.

### 실무상 함의

- **상대 측정(로컬 영점 기준 Δ)에는 영향이 없다.** 잡음 6~11 mA, 재현성 σ 0.5 LSB 로 이전
  세션과 동등하다. 구동 전 `Z` 를 치는 기존 절차를 지키면 좌우 비 같은 지표는 그대로 유효하다.
- **절대 전류(8/14 교정의 0 A 절편 기준)는 지금 쓸 수 없다.** `QUIET_GP28/GP27` 상수와
  `V_RAIL_REF` 가 현 회로에서 성립하는지 확인되지 않았다.

## 6. 펌웨어와 호스트 도구의 환산이 어긋나 있다 (신규)

조치 #18 로 들어온 `rail_corr` 이 **일부 경로에만** 적용돼 있다.

| 경로 | `rail_corr` | 근거 |
|---|---|---|
| 펌웨어 `V` / `E` 행 | **적용** | `pico/main.py:284-286` (`to_eng`) |
| ROS2 `oroha_power` | **적용** | `power_node.py:268-269`, `#ZERO` 에서 파라미터로 받음 |
| `tools/oroha_bench.py` | 미적용 | `:92` |
| `test/volt_compare.py` | 미적용 | `:163` |
| `test/volt_monitor.py` | 미적용 | `:192` |
| `test/preflight.py` | 미적용 | `VOLT_GP26_V` 상수 직접 사용 |

오늘 `rail_corr` = 1.0114 이므로 **같은 raw 에서 두 경로가 1.14% (약 0.31 V) 다르다.**
실제로 같은 순간에 펌웨어 `V` 는 27.92~27.94 V, 호스트 도구는 27.59 V 를 냈다.

DMM 27.14 V 기준으로는 **둘 다 높지만 호스트 쪽(+0.45 V)이 펌웨어 쪽(+0.79 V)보다 덜 틀렸다.**
이번 세션에서는 `rail_corr` 이 오차를 **키우는** 방향으로 작용했다.

> `oroha_fw/README.md` 는 "`v_per_lsb` 는 `#CFG` 를 따라가지 않는다"는 별개 문제만 적어 뒀다.
> **전압 경로의 `rail_corr` 불일치는 기재돼 있지 않다.** 새 상수를 넣을 때 어느 규약을 정본으로
> 삼을지 먼저 정해야 한다 — §4 의 `DIV_RATIO` 가 규약에 따라 11.1453 / 11.0644 로 갈린다.

## 재현 — 이번 세션에서 돌린 것

**전부 read-only 다. 모터가 도는 스크립트는 하나도 없다.**

```bash
python3 test/preflight.py --sec 30
python3 test/volt_compare.py --sec 45 --rate 50 -o <경로>      # A: raw 3027.74
python3 test/volt_compare.py --sec 30 --rate 50 -o <경로>      # B: raw 3021.76  ← DMM 과 짝
python3 test/div_ratio_solve.py                                # 계산 전용
```

`div_ratio_solve.py` 는 이번에 새로 만들었다. 하드웨어에 접속하지 않고 §4 를 재현하며,
저항값이 나오면 `--r1 <Ω> --r2 <Ω>` (또는 `--d <값>`) 로 레일까지 역으로 푼다.

`Z` 5 회 반복과 `V` 8 회는 임시 스크립트로 돌렸다 — 재현하려면 `mpremote` 로 직접 쳐도 된다:

```bash
mpremote connect /dev/ttyACM0 repl     # X → C → Z ×5 → V ×8 → G
```
